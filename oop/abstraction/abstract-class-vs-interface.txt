ABSTRACT CLASSES AND INTERFACES
===============================

Abstraction
-----------
Abstraction exposes what a type can do while hiding unnecessary details about
how it does it.

Abstract class:  Define a common structure for related classes, while forcing them to provide certain behavior themselves.
--------------
- Cannot be instantiated directly.
- Can have constructors, fields, concrete methods, and abstract methods.
- A concrete subclass must implement all inherited abstract methods.
- Use it when related classes share base state or implementation.
             Animal
        ┌─────────────────┐
        │ COMMON          │
        │ eat()           │  ← shared implementation
        │                 │
        │ REQUIRED        │
        │ sound()         │  ← child must implement
        └────────┬────────┘
                 │
          ┌──────┴──────┐
          ↓             ↓
        Dog            Cat
       Bark            Meow












Abstract class = common base + required behavior.
Interface = contract/capability.




Interface:  An interface defines a contract: any class that implements it promises to provide certain behavior.
---------
- Defines a contract or capability that implementing classes provide.
- A class may implement multiple interfaces.
- Methods without bodies are implicitly public and abstract.
- Modern interfaces may also declare default, static, and private methods.
- Use it to describe a capability that may be shared by otherwise unrelated
  classes.

Quick comparison
----------------
Abstract class: "is a" shared family/base.
Interface:      "can do" capability/contract.
